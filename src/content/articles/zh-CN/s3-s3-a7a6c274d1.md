- 许多 S3 兼容服务缺少 AWS S3 的 Block Public Access 等安全控制：Nebius 和 Cloudflare R2 允许公开桶但不允许匿名列举，DigitalOcean 支持公开可列举桶，Vultr 同时支持 ACL 和桶策略。
- Crusoe 和 Lambda Labs 完全缺乏公共访问能力，一些服务提供的保护少于 AWS S3 的 Block Public Access。
- S3 兼容服务的访问密钥常缺乏 AWS 密钥的结构化格式和秘密扫描模式，使得 GitHub 等工具更难检测到它们。
- IAM 能力和语义在不同 S3 兼容实现中有所不同，MinIO 的权限提升和 RustFS 的租户隔离漏洞等过往安全问题说明了风险。
- Wiz 的审查未覆盖 Backblaze B2、Wasabi 或 Google Cloud Storage。

开发者在评估 S3 兼容服务时，应审查其安全功能，尤其是公共访问控制和密钥管理，并考虑 IAM 语义的差异。
